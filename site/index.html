AI enablement operations, working demo

Messy AI tool requests in.
A clean, labeled, owned queue out.

One desk for the ops side of rolling out AI tools to a sales team: what we pay for, who actually uses it, what people are asking for, which shared prompts need an owner, and the weekly update that tells everyone. Same rules as the Python CLI, running right here in your browser.

Try it: send a request

Type anything a seller might ask about an AI tool. Watch it get redacted, classified, prioritized, labeled and routed, then land in the queue below. Nothing leaves your browser.

  1. Redactstrip emails
  2. Spot toolsmatch inventory
  3. Classifyrules first
  4. Prioritizeurgency + age
  5. Labelscoped labels
  6. Routequeue + DRI

Pick an example or write your own, then press Route it.

Request triage queue

Sorted by priority, then age. Scoped labels are the same ones the CLI can write back to a real issue tracker as a dry run first.

    Tool inventory and seat use

    Latest week of active users against paid seats. Anything under 40% gets flagged, and tools that do the same job get a consolidation proposal.

    Adoption trends

    Weekly active users over the last four weeks. Hover or tap a tool to isolate it.

    Prompt library health

    Prompts are process. Every shared prompt or agent needs an owner, a version and a review in the last 90 days, the same way a handbook page does.

    The weekly update, written for you

    Generated from everything above. TL;DR first, decisions with a DRI, two-way doors called out. Ready to paste into an issue or handbook page.
